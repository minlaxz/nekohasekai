# Retire Hysteria2 from API-served VPN profiles pending investigation

We retire the entire Hysteria2 transport, including the inner `shadowsocks-hy2` outbound and the outer `hysteria2` connection. ShadowTLS will be the sole Transport, with Shadowsocks still providing Managed user authentication and traffic accounting. This supersedes ADR 0001 for the active deployment: we are removing the whole path, rather than exposing Hysteria2 as a direct proxy with a shared password.

The operator reported delayed or failed Hysteria2 connections when first opening the VPN and lower stability than Shadowsocks over ShadowTLS. The root cause has not been diagnosed. [Issue #65](https://github.com/minlaxz/nekohasekai/issues/65), labelled `needs-triage`, records the symptoms and investigation starting points. Hysteria2 may return after that investigation; this retirement does not resolve or close the reliability issue.

The retirement implementation is tracked in [issue #66](https://github.com/minlaxz/nekohasekai/issues/66). Outbound naming and removal of the now-redundant `Proxy` group are a separate follow-up in [issue #67](https://github.com/minlaxz/nekohasekai/issues/67).

Existing deployments will use a one-time config volume rebuild rather than an automatic migration. The operator accepts losing generated configs, cached users, and traffic counters, so retaining migration code is unnecessary. With the updated Compose file and images, the upgrade procedure is `docker compose pull`, `docker compose down -v`, then `docker compose up -d`. The host's `.env` and bind-mounted `users.json` survive; the API restores Managed users recorded in that file. Users held only in the old ssm-api cache are lost. Deploy values must remain available in `.env` so ShadowTLS is recreated with the same settings.

The change removes Hysteria2 from client selectors, server inbounds and routing, initialization and certificate generation, required environment settings, Compose's published UDP port, and Hysteria2 requirements from active setup instructions. The previous setup instructions are preserved in `docs/research/hysteria2-deployment-before-retirement.md`. Tests verify the remaining ShadowTLS path and fresh-volume initialization without Hysteria2 settings. The glossary identifies the retired transport and describes the remaining active path. All Hysteria2 documentation and research are retained, including ADR 0001 and the general research and concept notes. The retirement is identified where needed to distinguish historical setup from current operation.

Cached client profiles must refresh to remove the retired path. A client pinned to Hysteria2 loses connectivity until it switches to ShadowTLS or refreshes its profile. Operators can remove the old Hysteria2 environment values and close its UDP port in the host or provider firewall.
