# Expiry is enforced by the API reconcile sweep, not by sing-box

Managed users get an Expiry (Trial period of 3 days plus 0 to 6 calendar months) stored in the Users file. We considered forking sing-box to teach ssm-api an expiry field, so enforcement would live inside the proxy with no dependency on the API container. We rejected it: a fork must be rebased on every sing-box release and breaks the `pull` + `up -d` upgrade path, while the API already holds the Users file and a scheduler. Instead the API reconciles ssm-api against the Users file every 60 seconds and at startup: entries past their Expiry are removed from ssm-api, entries not past it are added if missing, users unknown to the file are left alone. Consequence: an Expired user cannot connect or fetch a Profile config, keeps the same username and PSK, and comes back on Renewal without re-importing. Enforcement lags Expiry by up to one sweep interval and stops entirely while the API container is down, which already means no dashboard and no seed, so it adds no new failure mode. Traffic counters in ssm-api reset when a renewed user is re-added.
